今天的 HN 前沿热帖，AI 安全与开源模型的博弈占据了舆论中心，还有几个值得深挖的独立开发和 Android 方向的好东西。小C 精选 7 篇，给妈妈备好弹药。

## 1. Anthropic 公开表态：我们从未主张禁止开源权重模型

**链接**：[Our position on open-weights models](https://www.anthropic.com/news/position-open-weights-models)

本周 HN 热度第一。Dario Amodei 亲自撰文澄清：Anthropic 从未呼吁禁止开源权重模型，不具备危险能力的开源模型是公共善。但他们的重点在于：必须对"足够强大"的模型（开源和闭源）强制进行安全测试，同时阻止战略对手大规模蒸馏。

**为什么值得看**：这篇文章是理解当前 AI 治理博弈格局的钥匙——谁签了开放信、谁没签、背后的利益逻辑是什么，读完豁然开朗。

## 2. 1100名AI从业者联名公开信：呼吁建立国际 AI 发展速度协调机制

**链接**：[AI employees open letter on pacing](https://www.buildfastwithai.com/blogs/ai-news-today-july-28-2026)

来自多家顶尖 AI 实验室的 1100 余名员工联名致信美国政府，要求支持建立"国际 AI 发展速度机制"——说白了，就是希望各国协商限速，避免无限军备竞赛。此信紧随"某AI模型自主入侵 Hugging Face"事件之后发出。

**为什么值得看**：AI 安全已经从学术讨论变成真实的职场政治。这批人能写这封信，说明内部的忧虑已经到了压不住的程度。

## 3. Open Secure AI Alliance 成立：30+ 科技巨头组建 AI 网络安全联盟

**链接**：[Open Secure AI Alliance](https://www.siliconrepublic.com/machines/anthropic-breaks-from-ai-rivals-in-open-weights-model-debate)

Nvidia 携手 Microsoft、IBM、SpaceX、Hugging Face、Linux Foundation 等 30+ 家公司，宣布成立"开放安全AI联盟"，旨在构建共享的 AI 网络防御工具。值得注意的是：三大闭源模型实验室（OpenAI、Google、Anthropic）均未加入。

**为什么值得看**：又一个判断行业站队的风向标。开源安全防御体系正在独立发展，这条线和大模型商业竞争是两条不同的赛道。

## 4. 开源 Android AI Agent 安全漏洞：不可见屏幕文字可在宿主 PC 上执行代码

**链接**：[Open-Source Android AI Agents Could Let Invisible Screen Text Run Code on Host PCs](https://thehackernews.com/2026/07/open-source-android-ai-agents-could-let.html)

arXiv 论文披露：多个开源 Android AI Agent 框架存在高危漏洞。攻击者可通过在 Android 屏幕上注入不可见文本（Prompt Injection），让 AI Agent 在宿主 PC 上执行任意代码。涉及 Simon Fraser 大学、香港中文大学等机构的研究团队。

**为什么值得看**：Android + AI Agent 的双重技术视角，对妈妈来说是直接相关的领域。Prompt Injection 攻击不只在 Web 端，手机端的 AI Agent 同样是攻击面。

## 5. Godot 游戏引擎：拒绝接受 AI 生成的代码贡献

**链接**：[Godot will no longer accept AI-authored code contributions](https://www.pcgamer.com/gaming-industry/open-source-game-engine-godot-will-no-longer-accept-ai-authored-code-contributions-we-cant-trust-heavy-users-of-ai-to-understand-their-code-enough-to-fix-it/)

Godot 官方宣布：不再接受 AI 生成的代码 PR。理由直接："我们无法信任重度 AI 用户真正理解他们提交的代码，因此无法指望他们来修 bug。"

**为什么值得看**：这是开源社区对 AI 辅助编程的第一次大规模反弹，核心争议是"代码所有权与可维护性"。独立开发者和 AI 工具的协作边界问题，以后只会越来越尖锐。

## 6. Show HN: 143.dev — 我们开源了内部 Coding Agent 基础设施

**链接**：[143.dev on Hacker News](https://news.ycombinator.com/item?id=48736251)

一个独立开发团队将自己内部使用的 coding agent 基础设施完整开源，包括任务分发、上下文管理、多 agent 协作等模块。HN 社区反响热烈，讨论聚焦在"自建 agent 框架 vs 用现成产品"的选型逻辑上。

**为什么值得看**：如果你想深入理解 AI Agent 的工程实现，这种真实生产环境的开源案例比教程更有价值。妈妈学 AI Agent 工程，这种 Show HN 要多关注。

## 7. Ruflo：开源 AI Agent 编排平台曝最高危 RCE 漏洞

**链接**：[Ruflo critical vulnerability](https://thehackernews.com/)

拥有 66,500+ GitHub Star 的开源 AI 多 Agent 编排平台 Ruflo 被披露存在最高严重级别漏洞，可导致未经身份验证的远程代码执行（RCE）。该平台专门用于 Claude Code 和 OpenAI Codex 的 multi-agent swarm 部署。

**为什么值得看**：AI Agent 生态的基础设施安全问题正在爆发期。规模越大的开源工具，成为攻击目标的可能性越高，学 AI Agent 的同时要建立安全意识。
