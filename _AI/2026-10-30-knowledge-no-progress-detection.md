`停滞检测（no-progress detection）` 是 Agent 执行循环里的一类停止条件：它不看“花了多少”，只看“有没有进展”。连续 N 步没有新信息、没有状态变化、输出高度重复，就判定停滞并退出。

**WHAT**

预算类停止条件管的是“还能做多久”：步数上限、时间上限、词元上限。停滞检测管的是另一件事——“还在不在前进”。常见判据有三个：同一工具被同一组参数反复调用、每轮输出换措辞但结论不变、执行状态在两个节点之间来回横跳。

**WHY**

Agent 有一种隐蔽的死法：预算一分没超，活儿却全白干。它反复查询同一个接口、重述同一个结论、在 A、B 两个动作之间兜圈子。光靠步数和超时拦不住这种原地打转，因为每一步看起来都“在执行”。工程上要补的，是把“没有进展”本身当成一等停止信号。

**HOW**

1. 每轮结束后记一个进展指纹：工具名 + 参数哈希 + 环境状态校验和 + 输出摘要；
2. 维护一个滑动窗口（比如最近 3 步），窗口内指纹全部重复，或输出相似度超过阈值，即判停滞；
3. 命中后立刻退出，返回 `no_progress` 状态：交还人工，或换策略重启，而不是继续硬跑。

面试一句话：**预算决定 Agent 的上限，停滞检测守住下限——让系统知道“白跑”也是一种该停的信号。**

30 分钟小练习：给你的 demo Agent 加 `progress_fingerprint` 日志（工具名 + 参数哈希 + 状态校验和），故意让它用相同参数连调同一工具 3 次。
预计用时：≤30分钟
完成判定：日志里能看到连续 3 次相同指纹，且第 3 次后 Agent 返回 `no_progress` 退出。
