**WHAT：** 意图识别，就是在 Agent 真正调用工具之前，先判断用户这句话“想干什么”。输出可以是一个枚举标签（查询、下单、投诉、闲聊），也可以是一个结构化对象：意图名、关键参数、置信度。它相当于 Agent 的“前台接待”：先听懂，再转交。

**WHY：** 如果跳过这一步，让模型在生成回复的同时自由决定调哪个工具，短对话里还能蒙对，流程一复杂就会出问题：同一句话被路由到不同工具、参数靠猜、出错时很难分清到底是理解错了，还是执行错了。面试里能把意图识别讲成一层独立模块，说明你已经开始用工程方式管 Agent 的行为边界，而不是把所有责任都推给 Prompt。

**HOW：**
1. 先定义意图清单和触发样例，每个意图配 5~10 条典型说法；
2. 让模型先输出结构化意图（JSON：`intent` + `slots` + `confidence`），置信度低于阈值就追问或转人工；
3. 只有意图和必填参数都齐了，才放行到工具调用层。

面试一句话：**意图识别把“理解用户”从生成回复里拆出来，变成可测试、可拦截、可统计的一层路由契约。**

30 分钟小练习：给你的 Agent Demo 写一张意图表，列 3 个意图、每个意图 5 条样例、1 个必填参数和它的追问话术。
预计用时：≤30分钟
完成判定：表里有 3 个意图、15 条样例，且任意一句测试话都能被归到某个意图或触发追问。
