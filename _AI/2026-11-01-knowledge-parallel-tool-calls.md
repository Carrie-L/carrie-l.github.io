`并行工具调用（parallel tool calls）` 指模型在一次推理里返回多个 `tool_calls`，Agent 并发执行它们，再按各自的 `tool_call_id` 一次性回填结果。它和串行调用的差别在执行结构：等待方式从"排队"变成"齐头并进"。

**WHAT**

模型一次输出多个工具请求，例如同时查天气和查库存。Agent 端用 `asyncio.gather()` 并发执行，每个调用有独立 ID，结果回填时必须一一对应，不能张冠李戴。

**WHY**

面试真正考的是：什么时候敢并行。只读、互相无依赖的调用适合并行，延迟能省一大截；写操作、或后一个调用依赖前一个结果（先创建订单再支付）就必须串行。盲目并行会引入竞态、重复写入和 rate limit 打满，省下的延迟用错误买单。

**HOW**

1. 先分读写：只读 + 无依赖 → 并行；写操作或有依赖 → 串行；
2. 并发执行时控制并发度（建议 ≤5），超限排队；
3. 用 `return_exceptions=True` 做错误隔离，一个工具挂掉不拖死整批；
4. 回填结果按 `tool_call_id` 匹配，写入类结果串行落账。

面试一句话：**并行工具调用的本质是依赖图决定执行拓扑——模型只给候选，Agent 负责判断哪些能同时跑。**

30 分钟小练习：找一个串行 Agent demo，把其中 3 个只读查询改成 `gather` 并发，打印串行/并行延迟对比；写操作保持串行并记录执行顺序。

预计用时：≤30分钟

完成判定：日志里能看到同一轮并发执行 ≥2 个只读工具，并行延迟低于串行版本；写操作仍按顺序执行无交错。
