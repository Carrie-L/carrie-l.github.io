**WHAT：** 工具描述（tool description）是 tool schema 里写给模型看的那段说明文字。模型决定"调哪个工具"时，能看到的只有工具名、描述和参数列表——描述就是它选工具时唯一的信号源。

**WHY：** 描述写得含糊，模型就会选错工具，而且这类错误很难察觉：程序照常跑通，只是调了不该调的工具，或者该调的时候没调。当工具越来越多、职责越来越接近时（search 和 query、send 和 notify）， sibling 工具之间的边界全靠描述来划。面试里追问"你的 Agent 为什么会调错工具"，八成答案都落在描述工程上，这会显得你理解模型真实看到的输入。

**HOW：** 三条改写规则。其一，写清"什么时候用 + 什么时候不用"，否定句和肯定句一样值钱；其二，描述里塞 1~2 个具体使用场景，让模型有锚点可对；其三，与兄弟工具显式划界，例如 `search_notes` 负责查已有笔记，`write_note` 负责新建，描述里互相点名排除。改完别直接信，造几个边界提问回归测试：让模型在"更新一条旧笔记"这种两边都沾的场景里选，选对了才算描述合格。

面试一句话：**工具描述是模型选工具的唯一信号源，描述工程就是把歧义消灭在它到达模型之前。**

30 分钟小练习：打开你的 Agent Demo，挑 3 个工具，把每个描述改写成"用途一句话 + 两个使用场景 + 一个不使用场景"，再造 3 个边界提问验证模型选得对。
预计用时：≤30分钟
完成判定：3 个工具描述改写完成，边界提问下模型选工具正确 ≥ 2/3，并能口头说清每个描述排除掉了哪个兄弟工具。
