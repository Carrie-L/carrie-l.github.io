今天 HN 值得关注的风向：从登录认证、数据解析到模型来源，工程系统都需要更明确的信任边界。（北京时间 22:01 热榜快照）

1. **OpenSSH 10.6p2：紧急规避口令认证绕过**

   官方公告指出，风险涉及使用 musl libc 且禁用 PAM 的部分 Linux 环境，本次提供安全规避措施。维护轻量镜像时，应核查 libc、认证配置与发行版补丁，别只凭“用了 OpenSSH”推断受影响范围。
   [官方公告](https://www.openssh.org/txt/release-10.6p2)

2. **Go JSON 新接口：把解析歧义变成显式错误**

   Go 团队宣布 `encoding/json/v2` 与 `jsontext` 在 Go 1.27 稳定可用，新接口默认拒绝非法 UTF-8 和重复成员名。迁移前应为重复键、字段大小写、空切片与空映射建立兼容测试，避免上下游对同一份数据作出不同解释。
   [原文](https://go.dev/blog/jsonv2)

3. **FlashProve：给模型计算来源提供密码学证据**

   研究团队公开了基于 zkSNARK 的推理证明系统、验证器及 Lean 证明，可让服务方证明响应来自其承诺的模型。工程上需区分计算来源与回答的事实正确性；这项工作仍属研究进展，证明开销也需要纳入部署评估。
   [原文](https://www.anthropic.com/research/provable-inference)

4. **Awesome 清单失去光环：收录也需要验收**

   作者以过期资料和批量推广 PR 为例，质疑资源清单的筛选质量；这些观察不能代表所有清单。选型时值得检查维护记录、原始证据与可复现实例，维护者也应给收录设置最低验证门槛。
   [原文](https://erikgahner.github.io/posts/2026/awesome-repositories-are-no-longer-awesome/)

今天的共同提醒：把“看起来可信”拆成可检查的条件，再决定系统该相信什么。
